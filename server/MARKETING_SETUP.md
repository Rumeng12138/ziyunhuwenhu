# 商品排序、运费与活动

后台地址：`/admin`。

- **商品管理 → 调序**：输入排序号，0最靠前；相同排序号按商品ID升序。主键ID和历史订单关联不变。保存时检查是否已被别人修改，避免覆盖。
- **运费设置**：固定运费、满额包邮、全场包邮。金额最多两位小数；门槛以优惠后的商品金额为准。初始保留原规则：未满199元收12元，满199元包邮。没有自动新增地区差价。
- **活动管理**：新增、编辑、启用、停用优惠券、满减、商品折扣或包邮活动，可设开始/结束时间。日期按后台设备当地时间输入。新活动默认未启用；不预置实际折扣。
- **优惠券**：优惠码不区分大小写，可设门槛、减免额、总次数（0不限）和每人次数。优惠码由商家发给顾客；不公开全部优惠券。
- **商品折扣**：8.5代表八五折，可填适用商品ID，空白为全场。多个活动只取该商品最优惠的一档。

## 计价顺序

商品折扣 → 最优惠一档满减 → 一张优惠券 → 运费 / 包邮判断。

例如商品原价200元，八折后160元，满减20元、优惠券10元，最终商品金额130元。满199包邮时仍需运费。商品抵扣后至少保留0.01元，不产生负数或零元支付订单。

买家在确认订单页点击“使用”应用优惠码，显示完整明细。后端报价和下单均读取当前数据库价格和活动，拒绝前端伪造金额；规则变化时要求重新确认。成功下单后保存价格、优惠及运费快照，不因后续编辑活动而改变。

库存和优惠券使用次数在同一事务内预留。待支付、待商家核实的订单占用次数，取消订单释放次数；刷新或重复提交同一下单请求不会再次占用。未付款订单不会自动过期取消，须按现有取消流程处理。

## 登录与收款

普通支付宝/普通微信使用个人码，管理员核对官方账单后确认到账，不提供个人码自动到账回调。

商品、运费与活动操作不要求修改密码。收款码变更和人工确认到账需输入当前管理员密码。允许默认管理员凭据仅限本机开发：服务绑定127.0.0.1，管理员接口校验本站来源；生产模式拒绝默认管理员凭据。不会修改现有管理员密码。

若环境仍为演示JWT密钥，首次启动生成私有的 `data/session-signing.key`，旧会话需重新登录一次。部署应配置独立的随机JWT密钥，备份数据库、密钥及上传图片；不要公开这些文件。

## API

- `GET /api/admin/marketing`：运费、活动及优惠券占用次数。
- `PUT /api/admin/marketing/shipping`：`mode`、`fee`、`threshold`。
- `POST /api/admin/marketing/campaigns`：创建活动。
- `PUT /api/admin/marketing/campaigns/:id`：编辑活动，类型不变。
- `PUT /api/admin/marketing/campaigns/:id/enabled`：启用/停用。
- `PUT /api/admin/products/:id/sort`：`sort_order`、`expected_sort_order`。
- `GET /api/store-offers`：公开运费和有效非优惠券活动。
- `POST /api/orders/quote`：已登录买家获取购物车实时报价，可传`coupon_code`。
- `POST /api/orders`：下单携带报价的`coupon_code`、`quote_hash`。

自动化验证：在server目录运行 `.runtime/node.exe --test`。测试使用内存数据库，不产生真实支付。
