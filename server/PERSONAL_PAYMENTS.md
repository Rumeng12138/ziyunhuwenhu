# 普通收款与商户收款

| 后台与买家显示 | 接口标识 | 收款确认方式 |
| --- | --- | --- |
| 普通支付宝 | `alipay_personal` | 个人收款码，管理员核实官方账单 |
| 普通微信 | `wechat_personal` | 个人收款码，管理员核实官方账单 |
| 商户支付宝 | `alipay` | 支付平台验签通知或服务端查单 |
| 商户微信 | `wechat` | 支付平台验签通知或服务端查单 |

旧商户接口标识不变，历史订单不迁移或重新标记到账。商品列表、搜索和后台商品列表按可调整的排序号升序、相同时按数字ID升序分页，不改动原商品 ID。

## 启用普通收款

1. 后台 `/admin` → 收款设置 → 普通账户收款。已将本次提供的两张 PNG 原图保存到 `public/uploads/personal-alipay-initial.png`、`personal-wechat-initial.png`，首次初始化只添加预览，不自动启用。未覆盖已有配置。
   本次按用户要求，已在当前数据库启用普通支付宝和普通微信，保留现有收款码及说明。重新创建数据库时仍默认关闭。
2. 用手机试扫图片，核对账号和收款人。尤其注意支付宝图片中间的遮挡是否影响识别；本站不保证图片能被支付应用识别，也不验证收款账户归属。
3. 收款人名称可选，不填时提醒买家以支付应用显示的收款人为准；填写可选收款说明，勾选启用。输入当前管理员密码后保存。无需 APPID 或支付 API 密钥。
4. 可以上传 PNG/JPG 替换个人码，最大5MB。保存需要验证当前管理员密码，不要求本机用户修改密码。默认管理员仅允许本机访问，生产模式仍要求非默认管理员凭据。会话使用随机JWT密钥或自动生成的私有签名文件，不是支付平台密钥。

部署时带上 `public/uploads`，以及数据库及现有加密密钥的安全备份。收款码会被展示给顾客，属于公开收款信息；不要上传银行卡背面、密码、证件等无关敏感图片。

## 买家与管理员流程

买家创建订单预留库存 → 选择普通支付宝或普通微信 → 点击“确定支付” → 展示收款码、收款人、应付金额 → 买家在支付应用中扫码或识别图片后核对并转账 → 填写付款账单流水号 → 点击“我已付款，提交到账核实”。

前台显示“选择方式 → 扫码或转账 → 确认结果 → 支付完成”步骤。可复制金额、订单号并查看收款码原图；已发起的订单固定使用原支付方式，避免重复付款。付款窗口和“我的订单”每5秒刷新进度，切回页面也会查询。核实通过后显示“支付成功”，点击“完成，查看订单”返回订单列表。

支付成功代表已到账，实物订单状态为“已支付 · 待发货”，不自动跳过配送；发货后买家确认收货才成为“已完成”。历史订单没有有效收款凭据时不显示支付成功。

此时订单为 `payment_review`（待商家核实），没有标记已支付，不能发货，不计入已确认收入。买家自填的流水与说明仅帮助核对，不是到账证明。

管理员在订单管理筛选“普通收款待核实”，点击“核实收款”。必须登录自己的支付宝 / 微信官方账单逐笔核对：

- 确认到账：重新输入实际到账金额、官方收款流水号，勾选已核实并输入管理员密码。金额必须完全匹配；同渠道的同一流水不可用于多个订单。确认后显示“人工核实到账”，可以发货，计入收入。
- 未到账退回：填写原因，退回待支付，库存仍预留，买家可查看说明后重新提交。
- 未到账取消：填写原因，核实未收到款后取消，恢复库存一次。

收款码一旦展示就可能已经转账，因此买家不能再自动取消，管理员也不能用普通“取消”按钮跳过核实。普通码不能向平台自动关单；管理员取消后若发现迟到账，必须人工处理退款或重下单，不可直接把已取消订单改回已支付。本站不执行自动退款。

每次人工操作记录操作者、订单、决定、说明和时间。确认收款另记金额、实际流水。`payment_transaction_id` 仍只用于平台交易；人工收款使用独立字段，避免冒充平台验证。买家不返回管理员实际流水号和操作者 ID。

已经展示的收款码、收款人和说明会保存在订单快照中；后台换码或停用不改变旧订单，避免中途更换收款人。旧码文件不能删除，须保留用于订单核对。普通收款不支持动态金额二维码、自动查账或自动确认。

## 接口

- `GET /api/payment/methods`：四种方式及 `manual` / `provider` 模式。
- `POST /api/payment/pay`：普通方式返回订单收款码快照，不改变为已支付。
- `POST /api/payment/personal/:id/claim`：订单所有者提交 `reference`、可选 `note`。
- `GET /api/admin/personal-payments`：管理员查看设置。
- `POST /api/admin/personal-payments/qr`：管理员上传 PNG/JPG，multipart 字段 `file` 和 `admin_password`。
- `PUT /api/admin/personal-payments/:channel`：管理员保存 `enabled`、`qr_url`、`recipient`、`instructions`、`admin_password`。
- `POST /api/admin/personal-payments/orders/:id/review`：管理员传入 `decision`（`confirm` / `reject` / `cancel`）、`verified:true`、`admin_password`；确认另传 `amount`、`reference`，退回或取消另传 `note`。

本地测试不发生真实交易；启用普通码不等于已验证实际到账。
