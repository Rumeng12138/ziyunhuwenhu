# 生产投入使用清单

系统现在提供经营资料发布、上线检查、安全响应头、售后工单、退款凭证审计、数据库备份和敏感数据审计。以下步骤全部完成后，才可将站点作为正式商城公开收款。

## 1. 环境与账户

1. 使用 Node.js 22 或 24，并用仓库锁定的 pnpm 11 安装生产依赖；设置 `NODE_ENV=production`。
2. 设置至少 32 位随机 `JWT_SECRET`，不要提交到代码仓库。
3. 新生产数据库首次启动前设置 `ADMIN_INITIAL_PASSWORD`（12 至 72 字节，包含字母和数字）。生产环境不会创建 `admin / admin123`；初始化成功后该变量可以从平台删除。
4. 同源部署优先。设置精确的 `CORS_ORIGIN=https://正式域名`，生产环境不接受 `*`。
5. 设置 `PUBLIC_SITE_URL=https://正式域名`。Nginx 单层反向代理后设置 `TRUST_PROXY=true`，并确保代理覆盖客户端传入的转发头。
6. 首页展示与“店铺设置”的发布状态相互独立：五个默认版块首次启动即展示，后台“首页装修”仍可单独下线某个版块或子内容；已保存的首页内容、店铺公开资料和商品数据会在前台定时刷新。

## 2. 经营与法律资料

进入 `/admin` → **经营资料与上线检查**，填写并由经营方审核：

- 店铺名称、经营主体全称、实际经营地址；
- 可接通的客服电话、客服邮箱和服务时间；
- 真实备案号；
- 隐私政策、服务条款、售后政策、配送政策、发票政策。

品牌故事、文化文章和匠人访谈使用随程序提供的默认内容展示。投入真实业务前，应逐项核验人物、经历、资质、图片授权和文字真实性；不宜公开的版块应在“首页装修”中单独下线，不要把页面样例当作已核实事实。

“发布”只控制上线检查、搜索引擎收录与生产收款，不再控制首页是否可查看。店铺资料未全部完成时，已保存的公开字段仍会显示，空字段使用中性提示；未发布的站点会输出 `noindex`，生产环境也会拒绝创建付款。不得填写示例电话、地址、备案号、资质或无法兑现的服务承诺。

把所有上架商品的示例图片替换为商家拥有使用权的正式图片；缺图或仍使用 `picsum.photos` 示例图时，上线检查不会通过，生产环境拒绝收款。

## 3. 支付与售后

1. 至少配置一个经商户实际批准的收款渠道。
2. 用真实小额订单验证付款、签名回调、主动查单、商户账单和后台待发货金额一致。
3. 分别验证失败、超时、重复通知、关闭订单和金额不匹配场景。
4. 普通收款码始终需要人工核账，买家提交流水不代表到账。
5. 当前售后系统管理申请、退货物流、审核和退款凭证；商户退款 API 尚未自动调用。后台登记“已退款”前，必须先在支付平台完成真实退款并取得唯一流水号。

## 4. 数据保护与恢复

```powershell
pnpm run audit:sensitive
pnpm run backup:db
```

- `audit:sensitive` 只报告旧银行卡表是否存在及行数，不输出卡号等内容。
- `backup:db` 使用 SQLite 在线备份 API 写入 `BACKUP_DIR`；未单独配置时是持久化目录下的 `backups/`。生产环境应把备份同步到受控的异机加密存储。
- 在隔离环境实际完成一次恢复演练，并同时备份 `STORAGE_DIR`、环境变量、会话密钥和支付配置。
- 不要未经数据负责人批准直接删除旧数据库或备份中的敏感记录。

## 5. 发布与监控

```powershell
pnpm run sync:frontend
pnpm run build:admin
pnpm test
pnpm start
```

- `/api/health` 是存活和数据库连通检查。
- `/api/readiness` 返回逐项上线检查；正式切流前必须 `ready=true`。
- 为 5xx、支付回调失败、磁盘空间、备份失败和进程退出配置外部告警。
- 通过 Nginx/负载均衡器终止 HTTPS，只开放必要端口，并设置请求体和上传大小限制。

## 6. 当前仍需专项建设

多 SKU 库存、用户找回密码、管理员 MFA、微信 JSAPI/H5、支付宝移动网页支付、支付平台自动退款、物流轨迹、商品独立 URL/结构化数据和外部资源完全本地化尚未完成。如业务依赖其中任一能力，应在对应功能验收后再开放相关场景。
